# 📄 Document Q&A Chatbot (RAG)

A Retrieval-Augmented Generation (RAG) app that lets you upload PDFs and ask questions about them.
Answers are generated by an LLM using **only** passages retrieved from your documents, and every answer shows the source file and page number.

Built with **Python, LangChain, ChromaDB, Sentence-Transformers, Google Gemini and Streamlit**.

## How it works

```
PDF(s) ──► parse pages ──► split into overlapping chunks ──► embed (all-MiniLM-L6-v2)
                                                                   │
                                                                   ▼
Answer + sources ◄── Gemini LLM ◄── prompt(question + top-k chunks) ◄── ChromaDB similarity search
```

1. **Load** - `pypdf` extracts text page by page and keeps `source` and `page` metadata.
2. **Chunk** - LangChain's `RecursiveCharacterTextSplitter` creates overlapping chunks (default 1000 chars, 200 overlap).
3. **Embed** - `sentence-transformers/all-MiniLM-L6-v2` turns each chunk into a 384-dimensional vector, locally and for free.
4. **Store & retrieve** - vectors go into ChromaDB; the question is embedded and the top-k most similar chunks are retrieved.
5. **Generate** - a LangChain prompt template passes the question and retrieved context to Gemini, which is instructed to answer only from the context.

If no API key is set, the app runs in **retrieval-only mode** and shows the matching passages instead of a generated answer.

## Getting started

```bash
git clone https://github.com/krishnazi/docqa-rag-chatbot.git
cd docqa-rag-chatbot

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env             # Windows: copy .env.example .env
# edit .env and add your free key from https://aistudio.google.com/apikey

streamlit run app.py
```

The first run downloads the embedding model (~90 MB). Then upload `data/sample.pdf` (or your own PDFs), click **Process documents**, and ask something like:

- *What are the four steps of a RAG pipeline?*
- *Why does RAG reduce hallucination?*
- *What are the trade-offs of using RAG?*

## Configuration

| Setting | Where | Default |
|---|---|---|
| `GOOGLE_API_KEY` | `.env` | none (retrieval-only mode) |
| `GEMINI_MODEL` | `.env` | `gemini-2.5-flash` |
| Chunk size / overlap / top-k | Streamlit sidebar | 1000 / 200 / 4 |

## Tests

```bash
pytest
```

Tests cover chunking, PDF loading with page metadata, and the retrieval + generation flow (using fake embeddings and a fake LLM, so no API key or model download is needed).

## Limitations

- Works with text-based PDFs only; scanned PDFs need OCR first.
- The vector store is in-memory and rebuilt on each "Process documents" click. Pass `persist_directory` to `build_vector_store` to save it to disk.
- Answer quality depends on chunk size, top-k and the LLM; there is no automated answer-quality evaluation yet.

## Ideas for improvement

- Persist the index and support incremental uploads
- Add a re-ranker and hybrid (keyword + vector) search
- Compare retrievers built with LlamaIndex or FAISS
- Add answer-quality evaluation on a small question set
